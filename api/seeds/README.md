# Демо-контент для DEV-стенду

`dev_events.sql` — старий тонкий сід (20 подій, без соціалки). Лишається як історія.

**Актуальний сід — `demo.json` + `build-seed.mjs`.** 32 профілі, 76 подій у 22 містах,
47 з 49 категорій, квитки з ескроу-станами, підписки, збереження, дописи, коментарі,
лайки й відгуки. Половина подій у Києві, чверть — уже минулі (щоб було на що писати
відгуки), 20 безкоштовних із 76.

## Застосувати на DEV-стенді

```bash
bash scripts/seed-demo.sh
```

Скрипт: збирає SQL з `demo.json` → копіює на бокс → застосовує однією транзакцією →
перезапускає web (Next.js кешує `/api/events` на 300 с, інакше свіжий контент видно
не одразу) → друкує підсумкові лічильники.

**Він стирає наявний контент** (`DELETE FROM events` каскадом, плюс probe-акаунти
з безпекових прогонів). Перед цим сам робить `pg_dump` у `/opt/backups/`. Три постійні
акаунти — `user@`, `maker@`, `admin@underground.dev` — переживають сід; решта засіяних
акаунтів отримує ТОЙ САМИЙ пароль, що й `user@underground.dev`, бо сід копіює його
argon2-хеш (жодного секрету в репозиторії).

## Змінити контент

`demo.json` — звичайний JSON, правиться руками. Форма запису:

```jsonc
{
  "people": [{ "name", "email", "bio", "city", "is_organizer", "verified",
               "interests": ["electronic"], "avatar_seed" }],
  "events": [{ "title", "description", "category", "city", "venue", "cost_type",
               "price_uah", "tickets_total", "age_rating", "days_from_now",
               "start_hour", "duration_hours", "poster_seed", "organizer_name" }],
  "reviews":  [{ "event_index", "person_index", "rating", "text", "days_ago_after_event" }],
  "posts":    [{ "author_index", "kind", "text", "event_index", "days_ago" }],
  "comments": [{ "post_index", "author_index", "text", "hours_after_post" }]
}
```

Обмеження, які генератор НЕ виправляє мовчки — їх треба тримати самому:

- `category` — рівно один рядок із набору в `android/.../util/Category.kt`. Категорія
  поза цим набором рендериться сірим «іншим» і не ловиться жодним фільтром.
- `city` — місто має бути в газетирі (`cities`), інакше подія лишиться без координат
  і випаде з гео-ранжування. Українські міста додає міграція `0039_cities_ua.sql`.
- `age_rating` — тільки `""`, `"13"`, `"16"`, `"18"`, `"21"`. API валідує саме цей набір;
  старий сід писав `"18+"`, і воно проходило лише тому, що йшло повз API.
- `cost_type: "free"` ⇒ `price_uah: 0`.
- `days_from_now < 0` — минула подія. Відгуки дозволені ТІЛЬКИ на такі.

`build-seed.mjs` детермінований: без `Math.random`, увесь «випадковий» розкид — це хеш
від індексу. Той самий `demo.json` дає той самий SQL, тож діф сіду читається як діф даних.

Кількість квитків і `tickets_left` генератор тримає узгодженими: рядків квитків рівно
стільки, скільки «продано», інакше кабінет організатора суперечив би сам собі.
