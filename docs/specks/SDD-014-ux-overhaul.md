# SDD-014 — Концепція UX-перебудови (Фаза 2)

## Інформаційна архітектура (мобайл)

5 табів: **Афіша · Стрічка · Мої · Вхідні · Профіль**
- **Афіша** — пошук+фільтри (F-17b, наступна ітерація), категорії, без минулих подій.
- **Стрічка** — як є (підписки ∪ інтереси).
- **Мої** — Квитки | Мої події; інструменти мейкера прогресивно (скан/керування при ≥1 події).
- **Вхідні** (нове) — саб-таби Сповіщення | Повідомлення; бейдж = unread notifications+messages.
- **Профіль** — стіна + composer; пункти: Мої інтереси (ред. prefs), Повідомлення прибрано (→ Вхідні), Вийти.

Дуальність юзер⇄мейкер: прогресивне розкриття (див. аудит). Окремого перемикача немає.

## Стани екранів (обов'язково всюди)
Кожен список: loading (спінер) / empty (іконка+заголовок+підказка+CTA) / error (текст+Повторити) / content.
Спільні компоненти: `EmptyState`, `ErrorState`, `StatusBadge` (квитки/події), `Stat`.

## Дизайн-токени (поточна система; звірка з Figma — TASK-014-F)
- Фон #0B0B0D, surface #17171A, accent #2F6BFF (брендовий синій), muted #9A9AA5, error M3.
- Типографіка M3 default + wordmark UNDERGROUND (letterSpacing).
- Радіуси: картки 16-18dp, кнопки pill, чипи 50%.
- Дати: «9 чер», з часом «9 чер · 19:00» (укр скорочення місяців).

## Правила домену (нові, бекенд)
1. Минула подія (starts_at < now): прихована з афіші за замовчуванням (`?past=true` повертає),
   купівля/резерв → 409 «подія завершилась».
2. Відгук: лише після starts_at (422 «відгуки після початку події»); події без дати — без обмеження.
3. `GET /api/events/:id` — публічні деталі (404 для не-published для чужих).
4. `GET /api/me/unread` → `{notifications: n, messages: n}`.

## Веб-кабінет організатора (Фаза 3) — спека
`admin/` Next.js, розділ `/organizer` (логін будь-який юзер):
- **Дашборд**: к-сть подій, продано квитків, виручка, ескроу held/cleared (нове API `GET /api/organizer/stats`).
- **Події**: таблиця всіх своїх + CRUD (наявні API) + стоп-продажі/сховати/скасувати.
- **Квитки події**: `GET /api/events/:id/tickets` (organizer-only): покупець, статус, validated_at; CSV-експорт на клієнті.
- **Чати**: наявні conversations/thread API.
- **Виплати**: pos-MVP (черга payout requests) — після live-LS.
Беклог: TASK-014-W1 (stats API+tests), -W2 (tickets API+tests), -W3 (organizer UI).

## Адмін-панель платформи (Фаза 4) — спека
Розділ `/admin` (CurrentAdmin):
- **Dashboard**: GMV, комісія, юзери/події/квитки (`GET /api/admin/stats`).
- **Users**: список+пошук+пагінація, block/unblock, роль (`GET/PATCH /api/admin/users`).
- **Events**: список+статус-фільтр, hide/block (`GET/PATCH /api/admin/events`).
- **Orders/Escrow**: всі замовлення з фільтрами; дії refund/release/freeze (`GET /api/admin/orders`, `POST /api/admin/orders/:id/escrow`).
- **Settings**: платіжки+комісія (є) + per-organizer комісія (пізніше).
Беклог: TASK-014-A1 (admin stats/users/events/orders API+tests), -A2 (UI сторінки), -A3 (escrow-дії).

## Порядок реалізації цієї сесії
1. P0-фікси бекенд (домен-правила, /events/:id, /me/unread) + тести, 100%.
2. P0-фікси мобайл (Вхідні+бейдж, інтереси з профілю, статуси/дати укр, минулі події, мертві елементи).
3. Веб: organizer stats+tickets API з тестами; стартові сторінки organizer dashboard + admin users/events/orders (read-only список) — скільки влізе.
4. Гейти, деплой, скріни, звіт.
